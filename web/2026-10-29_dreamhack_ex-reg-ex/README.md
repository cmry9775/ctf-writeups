## 1. 문제 개요
Flask 앱이 입력 폼에 `re.match()`로 정규표현식 검증을 걸어두고, 그 패턴을 통과한 입력에 대해서만 플래그를 렌더링합니다. 패턴 자체를 분석해 조건을 만족하는 문자열을 직접 만들어내는 것이 목표입니다.

## 2. 정찰(Recon)
제공된 소스(`app.py`)에서 검증 로직을 확인했습니다.

```python
m = re.match(r'dr\w{5,7}e\d+am@[a-z]{3,7}\.\w+', input_val)
if m:
    return render_template("index.html", pre_txt=input_val, flag=FLAG)
```

- 입력값 `input_val`을 그대로 `re.match()`에 넣어 검사하고, 매치에 성공하면 그대로 `flag=FLAG`를 렌더링.
- `re.match()`는 **문자열의 시작 부분**이 패턴과 일치하기만 하면 성공

## 3. 취약점 분석
패턴을 토큰 단위로 분해하면:

| 토큰 | 의미 |
| --- | --- |
| `dr` | 문자열 "dr" |
| `\w{5,7}` | 영문/숫자/밑줄 5~7자 |
| `e` | 문자 "e" |
| `\d+` | 숫자 1자 이상 |
| `am@` | 문자열 "am@" |
| `[a-z]{3,7}` | 소문자 3~7자 |
| `\.` | 기호 "." |
| `\w+` | 영문/숫자/밑줄 1자 이상 |

`re.match()`는 *문자열 끝까지 검증하지 않**으므로 위 8개 토큰만 앞쪽에서 순서대로 만족시키면, 그 뒤에 무엇이 오든 매치에 성공합니다. 즉 "유효한 이메일인지"를 검증하려던 의도와 달리, 실제로는 "특정 접두 패턴으로 시작하는가"만 검증합니다.

CWE-625(Permissive Regular Expression) — 검증용 정규표현식이 끝(앵커)을 명시하지 않아 의도보다 훨씬 넓은 입력을 허용

## 5. 익스플로잇
1. 패턴을 토큰 순서대로 그대로 채움: `dr` + `\w{5,7}`(5자: `_____`) + `e` + `\d+`(`0`) + `am@` + `[a-z]{3,7}`(`abcd`) + `.` + `\w+`(`_`).
2. 완성된 입력값: `dr______e0am@abcd._`
3. 입력 폼에 그대로 제출 → 서버가 `re.match()`로 앞쪽 패턴 일치를 확인하고 통과 → 플래그 렌더링.

## 6. 방어 관점
- **근본 대책**: 전체 문자열이 패턴을 만족하는지 검증하려면 `re.fullmatch()`를 쓰거나, 패턴 끝에 `$`(또는 `\Z`)를 명시합니다.
  ```python
  # 기존(취약) — 앞부분만 맞으면 통과
  m = re.match(r'dr\w{5,7}e\d+am@[a-z]{3,7}\.\w+', input_val)

  # 개선 — 전체 문자열이 패턴을 만족해야 통과
  m = re.fullmatch(r'dr\w{5,7}e\d+am@[a-z]{3,7}\.\w+', input_val)
  ```
